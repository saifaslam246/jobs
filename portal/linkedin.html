Ludwig is a practice-management and patient-booking platform for physiotherapy clinics in Germany and Austria. 20+ therapists use it daily and it holds records for more than 10,000 patients.

It is three products against one backend and one clinical domain model:
• A practice dashboard where therapists run their day: patient records, clinical documentation, scheduling, resource management, absences, waiting lists and statutory health insurance invoicing
• A booking wizard a practice embeds in its own website, so patients book without ever seeing Ludwig
• Mobile apps for therapists

Two parts took the most thought.

Multi-tenancy. One deployment serves many practices and each practice's data stays strictly separated. In healthcare that is not a nice-to-have, so it shaped the data model from the start rather than being added later.

Offline-first. Treatment rooms often have no signal and a therapist still has to write notes. The app keeps working offline and syncs when it reconnects, with conflict handling so that when two people have edited the same record neither one's work quietly disappears.

Scheduling has more depth in it than it looks: recurring appointments, therapist absences, room and equipment availability, waiting lists, and computing free slots across all of that fast enough to draw a calendar without the user waiting.

Technologies: Angular 19, Ionic 8, TypeScript, Next.js 16, React 19, Flutter, RxJS, NgRx Signals, Tailwind CSS, Playwright, PDF workflows
